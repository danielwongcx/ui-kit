  • A scroll listener is the old way. It wakes the main thread on every tick, and the bar janks when that thread is busy.
  • This list names its scrollbar --page. The bar plays collapse on that timeline, with no scroll listener on the main thread.
  • Scroll 0 is the expanded bar: 8rem tall, title at 2rem. 50% of the first 6.25rem (100px at a 16px root) is halfway collapsed. 100% of that range, and anything past it, holds 4rem and a 1.5rem title.
  • The same link, without a name, is animation-timeline: scroll(block nearest).
  • Reduced motion snaps to the collapsed bar at the end of that range. Scroll still drives the change. Add ?reduce=1 to try it. ?motion=1 restores the smooth link.
  • Where animation-timeline: scroll() is unsupported, the bar stays expanded and the list still scrolls.
.scroller {
  scroll-timeline-name: --page;
  scroll-timeline-axis: block;
}

.app-bar {
  animation: collapse linear both;
  animation-timeline: --page;
  animation-range: 0 6.25rem;
}

.app-title {
  font-size: 2rem;
  animation: collapse-title linear both;
  animation-timeline: --page;
  animation-range: 0 6.25rem;
}

@keyframes collapse {
  to {
    height: 4rem;
    padding-block: 0.75rem;
  }
}

@keyframes collapse-title {
  to { font-size: 1.5rem; }
}
