View Transitions

Driftwood

A dark travel guide. Seven patterns, each one you can run.

The trick is view-transition-name. Same name means morph. Unique names mean track and move. The browser snapshots the old state and the new state and animates between them.

Reduced motion, including ?reduce=1, skips the animation. The screens still change.

Card becomes a page

Give the card picture and the detail header the same name. The group hero moves that box from the card into the page.

same name = morph

Same name, two snapshots

The browser keeps the old snapshot and the new snapshot. Width, top, and border-radius morph between them. On a wide stage that is about 353px to 100px, 137px to 15px, and 18px to 0px.

1 item = 1 nameeach row slides - 0 animation code

Every row its own name

Each saved trip has its own name. Sort and filter reorder the list. The rows slide. There is no animation code besides starting the transition.

Duplicate name = skipped / InvalidStateError. A repeated view-transition-name is skipped. A second startViewTransition while one is running throws InvalidStateError, or skips the first with AbortError.

1 rule - circular wipe

Theme toggle that spreads

Click the moon or the sun. The pointer sets --x and --y. A circle opens from that point and reveals the next theme.

clip-path: none does not interpolate, so the circle opens out to 150vmax. The old root stays put underneath.

origin = button

Modal born from the button

The share button and the dialog use one name for a single transition. The modal grows from the button.

Works across real page loads

This guides page, the Lisbon page, and the trips page each include @view-transition { navigation: auto; }. Open a card. Chrome 126+ and Safari 18.2+ morph the shared name. Other browsers swap instantly.
